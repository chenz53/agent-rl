This book is for engineers who already train language models and want to understand how to train agents: models that call tools, read observations, and act over many turns. It teaches RL from first principles while keeping the broader post-training workflow in view, including SFT, preference learning, and on-policy distillation.

I've spent years training foundation models, but agentic RL has not been my main focus. As agentic RL and post-training evolve, I've found it hard to find a systematic explanation that connects the theory, code, and practical decisions. This tutorial grew out of that gap. I created it together with GPT-6 to work through the subject carefully and share what I learn along the way.

The central question is concrete: **how does a coding agent's attempt to fix a bug become a learning signal?** We follow the entire path, from the model's generated tokens and tool results to trajectory tensors, verifier rewards, a loss, and a parameter update. The chapters build a small, tested training stack in PyTorch, with derivations, runnable implementations, and checked outputs. That connection makes it possible to explain both why an algorithm works and why a particular implementation can fail.

## What you should be able to do

After working through the code and exercises, you should be able to:

- **Build a training loop:** define a coding environment and verifier, collect multi-turn rollouts, construct training tensors, update the policy, and evaluate on held-out tasks.
- **Explain the objective:** derive policy gradients, advantages, PPO, and GRPO; trace which tokens contribute to the loss and how masks, normalization, and KL regularization change the update.
- **Make engineering decisions:** reason about tool budgets, reward design, long-horizon credit assignment, rollout freshness, and consistency between inference and training.
- **Diagnose failures:** investigate rising reward without better task performance, reward hacking, entropy collapse, and unstable updates using logs and controlled experiments.
- **Evaluate new methods:** separate established results from implementation choices and open questions, then design an experiment to test an alternative.

The goal is to prepare you to contribute to post-training research and engineering: implement a method, justify its assumptions, inspect its behavior, and test a proposed improvement. The small training stack gives you a system you can understand end to end; the real-model lab connects it to model-specific behavior. The final section of this page explains the limits of those experiments.

## How the book works

The book builds **one system**, one chapter at a time:

- **The BugFix gym** (Chapter 4) is a family of small Python repair tasks. The agent fixes them with the tools `read`, `test`, `edit`, and `submit`. Tests execute real code, a hidden test set guards against overfitting, and an exploit operation lets reward hacking happen for real.
- **TinyAgent** (Chapter 3) is a small transformer policy that is trained with RL on a CPU in about a minute. It shows the phenomena that large runs show: format learning, entropy collapse, length effects, credit assignment across turns, and reward hacking.
- **The real-model thread** uses the actual Qwen3-0.6B tokenizer and model wherever model-specific behavior matters, such as chat templates, tool-call tokens, retokenization drift, and the log-probability mismatch between the inference engine and the trainer.

Each mechanism is first derived, then implemented from scratch in a short code block, then run. Its printed output appears directly below the code. In the style of [D2L](https://github.com/d2l-ai/d2l-zh), a function built in one chapter is marked `#@save` and collected into the `agentrl` package, so later chapters call `arl.ppo_policy_loss(...)` instead of repeating it. By the capstone, the reader has written every piece of the stack. The generated package groups implementations into topic modules such as `policy.py`, `environments.py`, `trajectories.py`, and `grpo.py`; `__init__.py` only re-exports the API. See the module index (`agentrl/README.md`) for the chapter-to-module map.

Every chapter ends with **Design problems in practice**. This section takes problems engineers actually hit, and for each one it gives the symptom, the cause, the options, and a recommended default. Every chapter then gives a summary and exercises. [Appendix B](/tutorial/chapters/B-design-review) collects open-ended design-review problems, with model answers.

## Running the code

Every Python block runs. The checker executes the chapters in order, rebuilds `agentrl` from the `#@save` blocks of earlier chapters, and compares each block's stdout with the recorded output:

```sh
scripts/remote_check.sh <workdir> [chapter-prefix ...]   # runs on the GPU host; CPU is enough
python3 scripts/build_library.py                         # regenerate agentrl/ from the chapters
scripts/remote_figures.sh <workdir> [chNN ...]           # regenerate data figures
python3 scripts/build_tutorial_site.py                   # regenerate the Mintlify edition in website/
```

[The real-model lab](/tutorial/labs/README) trains Qwen3-0.6B on the BugFix gym on one H200, and Chapter 19 reports its measured results.

[The editorial guide](/tutorial/editorial-guide) defines the book's conventions, and [the source ledger](/tutorial/sources) records every external source with the date it was inspected and what was checked.

## What the experiments do and do not show

TinyAgent experiments are real and run on a CPU, but they are small. They demonstrate mechanisms and make failure modes reproducible. They are not benchmark results. Results reported by papers are labeled as reported, with dates. Recommendations are labeled as the book's recommendations. The environment executes only trusted code written for the book; Chapter 4 explains the isolation that real model-generated code requires.
