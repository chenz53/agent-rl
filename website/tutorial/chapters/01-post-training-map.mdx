---
title: "Post-training starts with a data-generating process"
---

A pretrained model already defines a conditional distribution over text. Post-training changes that distribution using demonstrations, preferences, task feedback, or a teacher. Before choosing an optimizer, identify who generates the training prefixes and who evaluates the output. Our running application is the existing synthetic oncology case; compact tensor laboratories isolate the mathematics without pretending to measure clinical skill.

## One task, several possible learning problems

SFT consumes demonstrations and increases their likelihood. Preference training consumes comparisons. Outcome RL samples the current policy and optimizes feedback from its interaction. On-policy distillation samples the student and asks a teacher to evaluate student-visited prefixes. A lab can mix these stages or alternate them; their order is an empirical recipe, not a universal law.

Consider a tool query that returns a record. In SFT, a demonstration can specify which table to query. In RL, a sampled choice is scored through the resulting task performance. In distillation, a teacher can supply a distribution over the next token at the student's actual prefix. These signals answer different questions, even when they all ultimately update the same transformer.

## The contract before the algorithm

Specify the task distribution, allowed information, sampling policy, evaluator, and held-out evaluation. For oncology, the prediction index excludes later outcomes from model context. The evaluator may access labels that the policy cannot access. A fluent teacher is not an outcome oracle: distilling its confidence can reproduce its errors.

The small experiment below makes the data source explicit. It prints metadata, not a real training result.

```python
routes = {
    "SFT": ("demonstration prefixes", "target tokens"),
    "Preference": ("paired responses", "pairwise judgment"),
    "Outcome RL": ("policy rollouts", "environment/evaluator reward"),
    "On-policy distillation": ("student rollouts", "teacher guidance"),
}
for name, (prefixes, signal) in routes.items():
    print(f"{name}: {prefixes} -> {signal}")
```

Output:

```text
SFT: demonstration prefixes -> target tokens
Preference: paired responses -> pairwise judgment
Outcome RL: policy rollouts -> environment/evaluator reward
On-policy distillation: student rollouts -> teacher guidance
```

## Design review

First establish a fixed-budget inference baseline. If supplying all relevant baseline records solves the task, incremental querying must earn its complexity through latency, cost, or information benefits. Distinguish a parameter update from an inference-time context change.
