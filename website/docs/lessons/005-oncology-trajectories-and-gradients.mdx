[Lesson 4](/docs/lessons/004-oncology-outcomes-and-reward) distinguished endpoints, statistical scoring, and evidence quality. This lesson asks how feedback can change the probability of earlier evidence-acquisition actions.

We keep the same oncology task. The sequence of actions and numerical rewards below are explicitly scripted teaching assumptions, not an autonomous rollout or a validated clinical evaluator. Use the existing vp Python environment for the PyTorch blocks; execute all blocks in order in one fresh session. No model weights are loaded.

## 1. Write down the complete interaction

An episode is the interval from initialization to ending. A rollout is policy execution and data collection. A trajectory is the saved sequence. Here is an illustrative trace: read pathology, read performance status, then submit an assessment. It is not claimed that those two tables alone are sufficient.

```python
trajectory = [
    {"action": "read pathology", "reward": -0.05},
    {"action": "read performance_status", "reward": -0.05},
    {"action": "submit assessment", "reward": 1.0},
]
for step in trajectory:
    print(step["action"], step["reward"])
print("total return:", round(sum(s["reward"] for s in trajectory), 2))
```

Output:

```text
read pathology -0.05
read performance_status -0.05
submit assessment 1.0
total return: 0.9
```

The final 1 is a stipulated success score used only to explain the mechanism. It is not derived from the patient's future outcome or produced by a clinical judge. The two costs are likewise hypothetical. Real rollout records must also preserve original generated IDs, sampling log-probabilities, policy version, masks, tool observations, and stopping reasons.

## 2. Factor the probability of this trajectory

For task x, environment E, and visible history h:

$$
p_\theta(\tau\mid x,E)=p_E(o_0\mid x)
\prod_t\pi_\theta(a_t\mid h_t)P_E(o_{t+1}\mid h_t,a_t).
$$

The model chooses actions; the environment returns observations. Our fixed record lookup is deterministic conditional on a valid table request. Suppose the action probabilities along this particular history are 0.4, 0.5, and 0.8:

```python
import math
probs = [0.4, 0.5, 0.8]
print("policy trajectory probability:", round(math.prod(probs), 6))
print("log probability:", round(sum(math.log(p) for p in probs), 6))
```

Output:

```text
policy trajectory probability: 0.16
log probability: -1.832581
```

The last probability is conditional on having seen the earlier records. It is not the probability of that same final answer from the initial prompt alone. A changed query policy changes later contexts and therefore the distribution of training inputs.

## 3. Why the environment does not need gradients

For a finite, undiscounted episode, let `R(tau)` be total reward and maximize:

$$
J(\theta)=E_{\tau\sim p_\theta}[R(\tau)].
$$

Assuming fixed environment/reward functions without direct parameter dependence and the usual differentiation conditions:

$$
\nabla J=E_\tau\left[R(\tau)\nabla\log p_\theta(\tau)\right]
=E_\tau\left[R(\tau)\sum_t\nabla\log\pi_\theta(a_t\mid h_t)\right].
$$

This is the score-function identity. We differentiate the probability of requesting `performance_status`, not the ECOG string returned by the database. That observation still affects later actions and reward. The environment influences learning through the sampled trajectory distribution even though its lookup function is not differentiated.

## 4. Return-to-go removes rewards an action could not affect

```python
rewards = [s["reward"] for s in trajectory]
gamma = 1.0
returns = [sum(gamma**(k-t)*rewards[k] for k in range(t, len(rewards)))
           for t in range(len(rewards))]
print("returns:", [round(x, 2) for x in returns])
```

Output:

```text
returns: [0.9, 0.95, 1.0]
```

The first query receives a weight based on all remaining rewards, 0.90. The second starts after the first cost, so its return is 0.95. The final answer starts after both costs, so its return is 1.00. In the standard on-policy estimator, removing past rewards from each action's weight removes noise without changing the expectation.

If only a final success reward is present, every preceding action receives the same return. That does not prove they all caused success. Discounting with gamma below one changes temporal preferences; a discounted objective requires consistent time weighting in its gradient derivation, not only a modified return formula.

## 5. Subtract a baseline without inventing new evidence

A baseline `b(h_t)` estimates typical return for the history and must not depend on the current sampled action for the standard unbiasedness argument:

$$
E_{a\sim\pi}[b(h)\nabla\log\pi(a\mid h)]
=b(h)\sum_a\nabla\pi(a\mid h)=0.
$$

The estimator becomes a sum of `(G_t-b(h_t))*grad log pi`. An independent or appropriately trained baseline can reduce variance. In a policy loss it is normally treated as constant; a value model has its own objective.

```python
baseline = 0.4
for outcome in [1.0, 0.0]:
    print(f"return={outcome:.1f} baseline={baseline:.1f} weight={outcome-baseline:+.1f}")
```

Output:

```text
return=1.0 baseline=0.4 weight=+0.6
return=0.0 baseline=0.4 weight=-0.4
```

A failed trace now has a negative weight rather than contributing zero in the simplest raw-return estimator. This changes estimator variance, not the amount of observed clinical evidence. GRPO's same-group mean includes the current sample, so this strictly action-independent proof must not be used to claim every GRPO estimate is unbiased.

## 6. Convert the gradient direction into a minimized loss

For current-policy samples and a local explanation:

$$
L=-\sum_t\operatorname{stopgrad}(G_t-b_t)\log\pi_\theta(a_t\mid h_t).
$$

The negative sign converts reward maximization into loss minimization. This small tensor treats log-probabilities as independent intermediate variables, not a complete normalized language model:

```python
import torch
logp = torch.tensor([-1.0, -0.7, -0.3], dtype=torch.float64, requires_grad=True)
weights = torch.tensor([0.6, 0.6, 0.6], dtype=torch.float64)
loss = -(weights.detach()*logp).sum()
loss.backward()
print("loss:", round(loss.item(), 6))
print("d_loss/d_logp:", [round(x, 6) for x in logp.grad.tolist()])
```

Output:

```text
loss: 1.2
d_loss/d_logp: [-0.6, -0.6, -0.6]
```

Gradient descent locally raises these log-probabilities. In an actual model, shared parameters mean one step need not increase every sampled action probability. Reusing an old batch after changing the policy also requires care: it is no longer a fresh sample from the current policy. Lesson 6 introduces the old/current ratio used in a controlled surrogate.

## 7. Credit assignment remains imperfect

Imagine a successful assessment whose first query was unnecessary. A terminal +0.6 weight still reinforces that query in this trace. Policy gradient is not a stepwise causal explanation algorithm.

Across many trajectories, unnecessary calls may fail to correlate with extra return; costs may reduce their value. To test necessity, define a controlled comparison: remove access to a table, substitute its contents, or hold a continuation policy fixed. Simply deleting a note and letting the model regenerate also changes its later behavior, so interpretation requires care.

## 8. Tool text is context, not a sampled action

A generated JSON request has token likelihood:

$$
\log\pi(a\mid h)=\sum_j\log p(y_j\mid h,y_{<j}).
$$

For six illustrative positions, let the first two be generated query tokens, the next two tool text, and the last two generated answer tokens. All six belong to context, but only four are sampled policy actions:

```python
logp = torch.full((6,), -1.0, dtype=torch.float64, requires_grad=True)
response_mask = torch.tensor([1., 1., 0., 0., 1., 1.], dtype=torch.float64)
loss = -(logp * 0.6 * response_mask).sum() / response_mask.sum()
loss.backward()
print("action positions:", response_mask.tolist())
print("d_loss/d_logp:", [0.0 if x == 0 else round(x, 6) for x in logp.grad.tolist()])
```

Output:

```text
action positions: [1.0, 1.0, 0.0, 0.0, 1.0, 1.0]
d_loss/d_logp: [-0.15, -0.15, 0.0, 0.0, -0.15, -0.15]
```

Masking those tool likelihood terms does not remove tool text from attention. Tool representations may still receive parameter gradients through subsequent generated answers. Dividing by four action positions differs from dividing by six total positions; the latter would let observation length change loss scaling.

These are artificial positions, not tokenizer-verified oncology traces. A real rollout must retain original sampled IDs, avoid decode/re-encode assumptions, and align causal predictions with the next token. The complete autonomous loop remains a future milestone.
