title: "Oncology export data contract"
---

Version 1, 2026-09-28. This is a local, entirely synthetic teaching schema. It is neither a hospital export specification nor an OMOP/MIMIC implementation. The active endpoint is provisionally 180-day all-cause mortality at a fixed pretreatment index.

## Directory and access boundaries

- `fixtures/oncology/clinical/`: 13 gzip CSV clinical tables; the only directory read by the agent-facing projection.
- `fixtures/oncology/evaluator_only/mortality.csv.gz`: evaluator-only follow-up and death records.
- `fixtures/oncology/manifest.json`: maintainer metadata, including raw counts; not agent context.

The reader uses an explicit table allowlist, not a recursive scan of every `csv.gz` file. A model requests a table name; the environment supplies patient and index. This is application-level isolation. Production execution must also restrict filesystem/tool access so an agent cannot bypass it with a shell or arbitrary file reader.

## CSV and temporal conventions

UTF-8, header row, comma-separated fields, standard CSV quoting, and empty string for absent values. Numeric fields remain strings until typed validation. Timestamps are ISO 8601 with a timezone; fixture values use UTC. gzip is deterministic with mtime zero. No real identifiers or records are present.

The common columns below precede each table's specific columns, in exactly the listed order. The current loader enforces exact headers; it intentionally rejects incompatible exports rather than silently guessing a mapping.

| Common field | Meaning |
| --- | --- |
| record_id | Stable logical record within a table; part of the revision key |
| version | Positive integer revision, unique with table/patient/record |
| patient_id | Patient join key across tables |
| encounter_id | Optional encounter association; not sufficient for joining all longitudinal evidence |
| event_time | Occurrence time according to this table's declared semantics |
| available_time | First visibility of this particular version |
| record_status | active or cancelled |
| source_system | SYNTHETIC_EHR provenance marker |

Filter both event and availability times at the index, select the latest available version, then remove cancelled records. Do not choose the latest export version before applying the time cutoff: a later correction would overwrite the historical view. Invalid/missing clocks, duplicate revisions, malformed rows, and unexpected columns fail closed. No data quality failure is automatically scored as a clinical reasoning error.

## Evaluator-only mortality schema

| Column | Meaning |
| --- | --- |
| patient_id | Unique patient key in this outcome file |
| death_time | Observed death time, or empty if not observed |
| last_known_alive_time | Last affirmative follow-up establishing survival |
| ascertainment_end_time | End of outcome collection; not proof of individual survival |

The label builder validates temporal ordering and returns event observation, follow-up days, horizon, and death-by-horizon (`1`, `0`, or missing). A death exactly at day 180 counts as an event for this contract. Death after day 180 establishes a non-event at that horizon. Last known alive at day 60 with no death gives an unknown 180-day label, even if the export window extends to December.

## Deliberate data challenges

| Challenge | Example | Required handling |
| --- | --- | --- |
| Corrected result | ALB-002 revisions 1 and 2 | Keep revision 2 at the index |
| Mixed units | Albumin 35 g/L and 3.1 g/dL | Convert explicitly before comparing |
| Delayed result | LDH collected before index, available after | Exclude from baseline |
| Late-signed text | NOTE-002 | Exclude despite pre-index event time |
| Future clinical course | NOTE-003 | Exclude |
| Pending assay | BIO-002, later final revision | Expose pending version only |
| Order versus exposure | Draft order, future administration | Do not infer treatment receipt |
| Ordered imaging | Brain MRI ordered, not performed | No negative or positive result inferred |
| Sparse other patients | SYN-ONC-002 and 003 | No cross-patient joins or invented features |
| Early censoring | Last known alive at day 60 | Do not assign a negative horizon label |

## Real-data adapter work still required

Map actual source fields and terminology with clinical/data stewards; establish completeness, deidentification, licenses, timestamp meanings, note versioning, dose/unit conventions, tumor episode linkage, prior-treatment coverage, and mortality ascertainment. Explicitly distinguish problem-list history from encounter diagnoses and orders from administrations. Site/export differences should become adapter logic and validation, not prompt guesses.

The fixture reader scans small tables and materializes the selected view in memory. It does not provide warehouse-scale joins, query pagination, security certification, or a validated prognostic model. The complete walkthrough is [lessons 1-2](/docs/lessons/001-oncology-prognosis-from-files).
