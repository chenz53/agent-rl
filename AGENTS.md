# Working agreements

This repository is a single book, *Agentic RL: From Policy Gradients to Coding Agents*. Everything outside `tutorial/`, `scripts/`, the generated `agentrl/`, and the generated `website/` is out of scope.

- The English edition (`tutorial/chapters/`, `tutorial/README.md`) is canonical. An optional Simplified Chinese edition lives in `tutorial/zh/` (requested by the user on 2026-10-14). It translates prose only; code blocks, outputs, math, Mermaid, and figures are byte-identical to the English edition and are verified there. When an English page changes, update its translation in the same change, then run `python3 scripts/check_translation.py --fix-anchors --require-all`. Use the term table and conventions in `tutorial/zh/glossary.md`. All other repository content is in English. Conversation with the user may be in Chinese.
- The reader is an experienced foundation-model engineer. Skip generic deep-learning introductions, and explain RL rigorously from first principles. The goal is a book after which a reader can contribute to a frontier post-training team.
- [tutorial/editorial-guide.md](tutorial/editorial-guide.md) is the writing and code contract. [tutorial/outline.md](tutorial/outline.md) assigns each chapter's scope, required design problems, figures, and the `agentrl` API. Keep both synchronized with the chapters when decisions change.
- The teaching method follows D2L without copying its text or code. Derive a mechanism, implement it from scratch in short blocks, run it, and interpret the output. Mark reusable definitions with `#@save` and import them in later chapters with `import agentrl as arl`. This replaced the earlier rule that every chapter redefines its functions; the user approved the change on 2026-10-13. A chapter may only use `agentrl` functions saved by earlier chapters, and saved signatures stay stable.
- Code blocks are short (5–20 lines, at most 30, and at most 40 for saved blocks) and make one point. Each printing block is followed by checked `Output:`. Never hand-write output. Verify with `scripts/remote_check.sh`.
- Every chapter has numbered sections, a "Design problems in practice" section (Problem/Symptom/Cause/Options/Default), a Summary, and Exercises.
- Figures are SVG with dark mode. Data plots use `scripts/svgplot.py` and its validated palette. Mechanism diagrams use the hairline style in `scripts/hairline.py` (isometric scenes or flat hairline cards, one accent stroke, callouts outside the drawing; adopted 2026-10-14 at the user's request, keeping all of each figure's information). Re-render selected figures with `scripts/remote_figures.sh <workdir> chNN:figure-name`. Data figures are computed by `scripts/figures/chNN_*.py`. Inspect every rendered figure (`scripts/preview_figure.sh`) before embedding it. Mermaid is fine for simple flows.
- The running system is the BugFix gym (Chapter 4) and TinyAgent (Chapter 3). The real-model thread uses Qwen3-0.6B from the remote Hugging Face cache, offline.
- Remote execution is via `ssh vp` (one H200, `/home/user/nanoAstra`, existing `.venv`). Use concurrent work directories under `/home/user/nanoAstra/.bookcheck/`. Never install packages, locally or remotely; a previous local installation was rejected.
- Distinguish measured results (printed by the book or saved under `tutorial/labs/results/`), author-reported results (cited with dates), and recommendations or hypotheses. Never report an experiment that was not run. Tiny CPU runs are mechanism demonstrations, not benchmarks.
- Record every external source in `tutorial/sources.md` with its inspection date and evidence boundary. Vendor-private recipes are unknown unless they are publicly documented.
- The environment executes trusted, authored code only. Real model-generated code requires process or container isolation, and the text must say so where execution appears.
- Display math uses `$$` on separate opening and closing lines. Preserve user formatting edits.
- `website/` and `agentrl/` are generated. Edit the chapters and rebuild them. Do not commit credentials, weights, or bulk rollouts. Do not create or publish a remote Git repository without a user request.
- The history of the earlier clinical and oncology material, design discussions, and experiments lives in Git history (before the 2026-10-13 cleanup), not in the working tree.
